# Domain documentation

Fine Vines uses a single domain context.

Before changing or describing the system:

1. Read the root `CONTEXT.md` glossary.
2. Read relevant decisions under `docs/adr/` when that directory exists.
3. Use the glossary's canonical terms in specifications, tickets, code, tests, and operational documentation.
4. Surface conflicts with an existing ADR rather than silently overriding it.

Missing ADR directories are not errors. Create an ADR only when a decision is consequential, difficult to reverse, or otherwise surprising enough to require durable rationale.
